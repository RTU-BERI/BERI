## Результат и границы

Публичная страница `/catalog` показывает карточки товаров, категории из API,
поиск по названию и фильтр по категории. Поиск применяется кнопкой «Найти»
или Enter; категория — сразу, вместе с уже применённым поиском. Ввод до
нажатия «Найти» считается черновиком. «Сбросить» очищает оба условия.
Есть загрузка, пустая выдача, ошибка с повтором, заглушка для отсутствующего
или сломанного изображения. Каталог доступен даже при ошибке проверки сессии.
Корень и неизвестный путь перенаправляются на `/catalog`.

Сохранены `/login`, `/register`, вход, выход и восстановление cookie-сессии.
Выход выполняется на странице аккаунта `/login`, доступной из общей навигации.
Подробности товара, характеристики, тариф, ПВ, наличие и ссылки на detail
не добавлены: это S1-P6. Бронирования, цен и остатков нет. Мобильная вёрстка
каталога не заявляется. Новых библиотек, изменений backend, моделей, миграций,
auth-клиента и API-контрактов нет.

Путь данных: React вызывает `getProducts` → общий `api` делает `fetch` на
`/api/products/` → Vite proxy передаёт запрос Django на 8000 → view фильтрует
PostgreSQL → serializer возвращает JSON-массив → React сохраняет его в state
(памяти компонента) → `ProductCard` рисует каждую запись.
Категории загружаются из `/api/categories/`; их ID сопоставляются с названиями.

Подтверждённый контракт: оба списка — массивы, без пагинации. Category:
`id: number`, `name: string`. Product: `id/category: number`, `name/status: string`,
`image_url/brand/model: string | null` (пустые строки тоже допустимы).
`ProductListAPIView` использует AllowAny и отключённую аутентификацию.
Поиск — `name__icontains`, категория — `category_id`, вместе — AND.

`URLSearchParams` безопасно кодирует русский текст, пробелы, `&`, `+` и другие
символы; например `/api/products/?search=...&category=2`. Постоянных товаров
в приложении нет. Тестовые массивы находятся исключительно в e2e-тесте.
Если backend изменит контракт, нужен согласованный контракт BERI-104-A:
сейчас зависимость доступна, блокировки интеграции нет.

`useEffect` — действие после изменения условий. Каждый запуск имеет свой
флаг `active`. При смене условий или уходе со страницы cleanup выключает флаг
предыдущего запуска: его поздний успех, ошибка и finally уже не меняют state.
Запрос физически может завершиться, но не перезапишет новый результат.
Это работает и с двойным запуском эффектов в React StrictMode.

Пока идёт запрос, старые карточки скрыты и видна загрузка. Ошибка одного из
списков не превращается в «Товары не найдены»; кнопка повтора заново получает
оба списка с текущими условиями. Empty показывается только после успешной
загрузки обоих списков. Несовместимый JSON также считается ошибкой.

## Запуск и показ

В обычном окружении с npm, Python 3.13 и собственной PostgreSQL:

1. Настройте backend/.env по README и docs/auth.md, примените существующие
   миграции к собственной локальной БД. Через Django Admin добавьте категории
   и несколько учебных товаров, статус active, фото можно оставить пустым.
2. Из backend с активированным venv: `python manage.py runserver` — для
   каталога достаточно. Для регистрации используйте локальные demo-настройки
   из docs/auth.md и `python manage.py run_local_demo 127.0.0.1:8000 --noreload`.
3. Во втором Git Bash: `cd frontend`, `npm ci`, `npm run dev`.
4. Откройте `http://localhost:5173/catalog`; используйте именно localhost,
   как в настройке proxy/cookies. Каталог не требует входа.
5. Покажите поиск, затем категорию с тем же поиском, пустой результат, сброс.
   Покажите `/login`, регистрацию с новым учебным номером, вход и выход.
   Ошибку загрузки можно показать, временно остановив Django и нажав повтор.

Для браузерных проверок держите Django и Vite запущенными:

```bash
cd frontend
npm run build
BERI_E2E_BROWSER=msedge BERI_E2E_PHONE='<новый_синтетический_номер>' npm run test:e2e
```

Перед повтором auth нужен новый синтетический номер и свежие demo-лимиты
(перезапуск demo-сервера). Для одного mocked-каталога Django не нужен:
`BERI_E2E_BROWSER=msedge npm run test:e2e -- e2e/catalog.spec.ts`.
Для live catalog нужна непустая demo-БД. Артефакты тестов не включаются в Git.

Commit, push, создание PR и merge не выполнены: §2 docs/Specification.md требует
согласования конкретного commit, ручного push и ручного PR. Все перечисленные

команды (код и безопасность), Documentation Gate и актуальные CI по защите ветки;
конкретные имена ревьюеров не заданы и не выдумываются.
