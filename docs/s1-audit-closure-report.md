## Что изменилось для пользователя

Правильные категории, поиск по названию и их совместная фильтрация работают
по-прежнему. Некорректный category теперь получает понятный 400 вместо аварии
сервера. Отсутствующий или ровно пустой category не фильтрует выдачу;
неизвестный допустимый ID даёт 200 `[]`.

Непустой category: 1–19 ASCII-цифр, значение 1…9223372036854775807.
Ведущие нули допустимы в пределах длины. Знаки, пробелы, дроби/экспоненты,
Unicode-цифры, ноль/отрицательные и слишком большие числа дают 400.
Ограничение длины проверяется до преобразования, поэтому 5000-значная строка
не вызывает Python integer-conversion error. [Точный контракт](API.md).

UI приложения, валюта, статусы, схема БД, permissions и session/CSRF не менялись.

## Причина keyboard-падения и границы исправления

В минимальном HTML без React воспроизведено: headless Chrome на macOS не
меняет native select через ArrowDown/Enter, Space/стрелки и Home/End. Это
OS-owned popup, не обработчик приложения. Обычная ASCII-буква в collapsed
select получает настоящий keyboard event и запускает встроенный type-ahead.
Playwright вставляет кириллический текст через insertText, что не равно
набору keydown для этого нативного элемента.

В одном keyboard-тесте используются синтетические названия `Pickup alpha` /
`Pickup bravo`. Повторное `p` циклически выбирает совпадения: 11→22→11. Это
устраняет зависимость от таймера накопления разных букв (`ab`). Не вызываются
selectOption, присваивание DOM value или ручной dispatch change. Все прежние
проверки Tab, Enter, Shift+Tab, focus outline, адресов/остатков и отсутствия
повторного availability-запроса сохранены. Остальные тесты проверяют исходные
русские названия ПВ. Код UI вообще не изменён.

Промежуточный вариант с разными ASCII-префиксами не прошёл 5 keyboard-повторов
из-за накопления type-ahead buffer; после замены на стандартный цикл одинаковой
буквы финальные пять keyboard-повторов и полный suite прошли. Неуспешный
промежуточный вариант не выдаётся за конечный результат.

Проверена клавиатурная доступность в заявленном автоматическом сценарии.
Ручной проход человеком по OS-popup, screen reader и полная WCAG-проверка не
проводились. Это остаётся границей проверки; native arrow-popup headless Mac
не объявляется подтверждённым. Изменять нативный UI ради ограничений тестового
драйвера не потребовалось.
